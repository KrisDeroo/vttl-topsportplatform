## Spacing Scale

Declared values (multiples of 4 only). Tailwind v4 default scale aligns 1:1.

| Token | Value | Tailwind | Usage |

| sm | 8px | `2`, `gap-2`, `p-2` | Form field internal padding; tight rows in tables |
| md | 16px | `4`, `gap-4`, `p-4` | Default card padding; default form-field gap |
| lg | 24px | `6`, `gap-6`, `p-6` | Card section padding; vertical gap between Card groups |

**Exceptions (declared, all on 4-pt grid):**

- DataTable row min-height: `h-12` (48px) for keyboard navigation comfort.

### Form-field contract

Every input MUST use the shadcn `Form` composition:

```
<FormField name="...">
  <FormItem>
    <FormLabel>...</FormLabel>
    <FormControl>{/* Input | Select | Calendar | RadioGroup | Checkbox | Textarea */}</FormControl>
    <FormDescription>{/* optional helper text — i18n key */}</FormDescription>
    <FormMessage /> {/* renders zod error message resolved via useTranslations('errors') */}
  </FormItem>
</FormField>
```

Required fields show a `*` after the label (rendered in `text-destructive`). Disabled (read-only-by-role) fields render the value as plain `text-foreground` inside a bordered, non-interactive `div` styled to look like an Input but with `aria-disabled="true"` — never a real disabled `<input>` (avoids a11y "you can't read this" pitfall in some screen readers).

## Photo Upload Widget — Interaction Contract (D-41)

**Component:** `<PhotoUpload userId={...} initialFileId={...} onUploaded={cb} disabled={...} />`

### Visual states

| State | Look | Copy key |
|-------|------|----------|
| Empty (no photo + idle) | Dashed border 2px (`border-dashed border-input`), `--muted` background, `lucide ImagePlus` icon (size 32) centered, hint text below | `files.photo.dropzone.idle` |
| Hover/dragging-over | Solid border 2px (`border-primary`), `bg-primary/5` background, same icon | `files.photo.dropzone.dragging` |
| Uploading (request in flight) | Border solid `border-input`, `bg-muted`, `Loader2` spinner + percentage if XHR progress available | `files.photo.uploading` |
| Pending scan | Avatar with the just-uploaded image (object-URL preview, **NOT** signed URL — scan not done yet), greyscale `filter grayscale opacity-70`, overlay Badge `scan_status: pending` | `files.photo.scanPending` |
| Clean | Avatar full color, neutral border, "Replace" + "Delete" icon buttons appear on hover (44×44 hit targets) | `files.photo.scanClean` |
| Infected | Red border 2px (`border-destructive`), faded image (`opacity-40`), `ShieldAlert` icon overlay, full-width destructive Alert below ("Bestand afgekeurd door scan — kies een ander bestand") with single CTA "Andere foto uploaden". Original blocked file is NOT reused as fallback. | `files.photo.scanInfected` |
| Disabled | Reduced opacity (`opacity-60`), no drop interaction, hidden hover affordances | n/a |

### Interactions

1. **Click on the dropzone** → opens native `<input type="file" accept="image/jpeg,image/png">` (single file).
2. **Drag over the dropzone** → state flips to "dragging-over" (CSS only, via `onDragEnter`/`onDragLeave` counter).
3. **Drop a file** → same handler as click. If multiple files dropped, take only the first; show a toast "Eén foto tegelijk" (`files.photo.errors.multiFile`).
4. **Client-side pre-check (UX hint, not authoritative — D-23):**
   - If `file.size > 2 * 1024 * 1024` → show inline error `files.photo.errors.tooLarge` (with the actual size formatted via `Intl.NumberFormat(locale, { style: 'unit', unit: 'megabyte' })`); do not upload.
   - If `!['image/jpeg', 'image/png'].includes(file.type)` → show error `files.photo.errors.wrongType`; do not upload.
5. **Upload** → call `trpc.file.upload.useMutation()` with the file (multipart). Server runs the magic-byte + size + Zod validation (authoritative); on success returns `{ fileId, scanStatus: 'pending' }`.
6. **Polling** → on receipt of `fileId`, start polling `trpc.file.getScanStatus.useQuery({ fileId }, { refetchInterval: 2000 })`.
   - Stop polling once status ∈ `{'clean', 'infected'}` OR after 30 seconds (timeout state — show `files.photo.scanTimeout` with manual "Refresh" button).
   - On `clean`: emit `onUploaded(fileId)`; toast `files.photo.toast.uploaded`.
   - On `infected`: render the Infected state above; do NOT emit `onUploaded`. The owning form keeps the previous `profile_photo_file_id` value so the persisted profile stays clean.
7. **Replace** → opens the same picker; on submit, the *previous* `uploaded_files.id` is marked `superseded_at` server-side (D-29), the form's `profile_photo_file_id` updates to the new id only after `clean`.
8. **Delete** → confirms via `AlertDialog` (`files.photo.deleteConfirm.title` / `files.photo.deleteConfirm.body`); on accept, sets `profile_photo_file_id = null` via `player.update`/`trainer.update`. The `uploaded_files` row gets `superseded_at` (audit-trail per D-29).

### Accessibility

- Dropzone is a `<button type="button">` (not a `<div>`) so keyboard users can hit Enter/Space to open the picker.
- `aria-describedby` points to a hidden helper text that announces "PNG of JPEG, max 2 MB".
- Polling state is announced via `<div role="status" aria-live="polite">` so screen readers hear "Scan voltooid — foto opgeslagen" without a refresh.
- Error states use `aria-invalid="true"` + linked `<FormMessage>` (when nested in a Form).
- Focus ring uses `--ring` token — never removed.

## Localization Contract (I18N-06, I18N-08)

### Message-catalog namespaces added in Phase 2


> **Audit note for the planner:** Phase 1 ships `lookups.status.*` (line 58 of `messages/nl.json`); Phase 2's `## Copywriting Contract` table refers to that same path — do NOT branch into `lookup.status.*`. The other Phase-2-new lookups (`lookup.academy.*`, `lookup.age_category.*`, `lookup.trainer_diploma.*`) sit under the singular `lookup.*` root for consistency with CONTEXT.md D-44. The planner should resolve this naming inconsistency in its first wave (rename `lookups` → `lookup` OR keep `lookups` plural and update D-44). Either choice is acceptable; the spec just requires consistency in one direction.

### Proper-noun rule (I18N-06, D-45)

Academy names, club names, person names render IDENTICALLY in nl, en, fr — they come from canonical `display_name` columns (academies) or `users.first_name` + `users.last_name`. The lookup-label resolver MUST NOT lowercase, transliterate, or alter these strings. If a label is missing in fr.json (e.g. `lookup.academy.topsportschool` is `Topsportschool` in nl), the canonical Dutch string is the correct fr/en value too — copy it verbatim into all three catalogs (do NOT leave the key absent and rely on a fallback).

### Date display

Single source: `src/lib/i18n-format.ts` (Phase 1) — re-export `formatDate(date, locale)` and use it in all read-only date renders (DOB on profile header, `effective_from` in age-category history, `uploaded_at` on photo metadata). Format `dd/MM/yyyy` for all three locales (Belgian convention even in en-GB context). Datepickers use the same format.

### Zod messages → i18n keys (I18N-08, D-46)

Every shared schema in `src/server/trpc/schemas/` emits keys, not strings:

```ts
z.string().min(1, { message: 'errors.field.required' })
z.string().email({ message: 'errors.field.email' })
z.coerce.date().max(new Date(), { message: 'errors.field.dateInPast' })
z.string().regex(/^[0-9]{4}$/, { message: 'errors.field.belgianPostalCode' })
```

Client side: `react-hook-form`'s `formState.errors[field].message` is the key; `<FormMessage>` (or its successor) calls `useTranslations('errors')(message)`. Add a tiny adapter in `src/lib/forms/zod-i18n.ts` so `<FormMessage>` does the lookup automatically.

> **Failure-mode declared:** If a key is missing in dev, the Phase 1 fail-loud fallback (D-20) renders `MISSING_KEY:nl.errors.field.required`. The Phase 8 CI gate (I18N-10) blocks merges with missing keys. This means the planner MUST add Phase 2 keys to all three catalogs in the same wave as the form components.

## RBAC-Sensitive UI Behavior (D-37, D-38, D-36)

The UI MUST trust server scope decisions (RLS + tRPC checks) and reflect them visually. The component contract:

| Caller role | Player list | Player detail (in scope) | Player detail (out of scope) | Player edit |
|-------------|-------------|--------------------------|------------------------------|-------------|
| TD | full list | full read | n/a (everything in scope) | full edit form |
| academy_manager | scoped list | full read | 404 page rendered (`errors.notFound` empty state — copy identical to "geen spelers") | full edit form |
| trainer | scoped list (read-only — no actions column for create/edit) | full read; **no edit affordance shown** (form rendered as read-only `aria-disabled` view) | 404 page | n/a — edit route returns 404 |
| player (self) | redirected to `/me/profile` (no list view) | n/a | 404 | edit form with non-sensitive fields only (D-37) |
| parent of player | redirected to child's `/players/[id]` if exactly one minor child; otherwise list of own children | full read of own child | 404 | edit form with non-sensitive fields + emergency contact |

**Visual rule for read-only forms:** the form looks identical to the editable version except:
1. No primary submit Button rendered.
2. Inputs/Selects rendered as styled non-interactive divs (the same "looks like an input but isn't" pattern from `## Component Inventory`).
3. Header pill: `Badge variant="outline"` reading `players.detail.readOnly` ("Alleen-lezen" / "Read-only" / "Lecture seule") next to the H1.

This guarantees that a trainer landing on a player profile understands at a glance what they can and cannot do, **without** the page having to discover scope client-side. The Server Component owns the `mode` prop and the Client form respects it.

## Loading & Error States

### Loading (every list + detail page)

- Use shadcn `Skeleton` for:
  - List rows: 8 skeleton rows, each `h-12` with avatar circle + 3 text bars.
  - Detail header: avatar circle (96×96) + 24px text bar (name) + 14px text bar (status).
  - Card bodies: 4 skeleton lines per Card.
- Skeletons render in the same dimensions as the real content (no CLS).
- Maximum visible loading time before showing skeletons: 200ms (Suspense boundary timing — implementation detail for the planner).

### Error (network / auth)

- Page-level fetch error: render `ErrorBoundary` fallback with `errors.generic` heading, "Probeer opnieuw" / "Try again" / "Réessayer" Button (`Button variant="outline"`). Sentry captured server-side per Phase 1.
- Form-submit error: shadcn `Sonner` toast variant `error` with `players.edit.toast.error` (above). The form retains its values; nothing is dropped.
- 403 from API (should be rare since RLS returns 0 rows = 404): same toast with `errors.forbidden` (already in Phase 1 catalog).
- 404 from `player.get` / `trainer.get`: full-page Empty State with `errors.notFound` and a back link to `/players` / `/trainers`. Visually indistinguishable from the "no spelers in scope" empty state (D-36).

## Accessibility Contract

- All interactive components are reachable by keyboard. Tab order follows DOM order (no `tabindex` > 0).
- Color is never the only signifier — every state-conveyed-by-color (scan_status, minor flag, required field) also has an icon or text marker.
- Contrast: `--foreground` on `--background` clears WCAG AA at body sizes (oklch L ≥ 0.85 difference). The neutral preset is audited by shadcn upstream.
- Form errors are linked to inputs via `aria-describedby` (the shadcn `Form` composition handles this automatically when used as documented).
- The `<PhotoUpload>` widget announces state changes via `aria-live="polite"` (uploading, scan complete) and `aria-live="assertive"` for the infected state.
- Dialogs trap focus and restore it on close (Radix Dialog default).
- The 44×44 minimum hit-target rule applies to: photo replace/delete icon buttons, age-category-change icon button (TD), and any future destructive icon-only button. Hover-only affordances (the action buttons that appear on photo hover) MUST also be reachable via keyboard focus on the Avatar (`focus-within` triggers visible state).
